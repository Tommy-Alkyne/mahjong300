## 做了什么

把《麻雀 傑作「何切る」300選》的 300 道题做成单题网页：一屏一题、点牌作答、答案折叠、进度与星标存后端跨设备同步。前端是纯静态 HTML/CSS/JS，后端只有一个 `serve.py`（`ThreadingHTTPServer`，无第三方依赖）。

## 设计要点

### 已做与对错

- 已做：点牌选牌、或展开答案 → 自动记已做；题号行右侧按钮可手动改（「标为已做 / 已做·点此取消」）
- 对错：所选牌与题目数据里的推荐牌同牌即算对（红五按 5 比较）；副露题（`original_only`）或没有选择记录时只标「已做」。判定由前端拿 `choices[题号]` + 题目数据现算，不额外存字段
- 开场落在**第一道未做**，不是上次那一题；底栏「跳到最新」= 最大已做题号 + 1

### 进度存储

- 存**后端** `GET/POST /api/progress` → `progress.json`，形如 `{done:{题号:1}, stars:{题号:1}, choices:{题号:下标}, current, updated}`
- 前端只在内存留运行期状态：选择/标记后**立即** POST（不等切题），切题类变更 400ms 去抖，关页用 `sendBeacon` 补写
- 回到前台（`visibilitychange` / `focus`）重新 GET 对齐，页面一直开着也能看到别的设备做的进度
- 旧版 localStorage 进度在首次加载时一次性并入后端并清掉本地键（`heqie-migrated-v1`）；更早的版本只记位置（`heqie-current-v1`，≤31）时，把 1..n-1 补记为已做

### 合并语义（2026-11-08 修）

POST 不再是整份覆盖：`done`/`stars` 取并集，`removed`/`unstared` 显式删除，`choices`/`current` 以本次写入为准，响应返回合并结果供前端采用。

事故来源：11-08 10:23–10:54 手机做了 1—49 题并写后端；12:27 另一台电脑带着自己的旧状态打开，整份覆盖把这批记录冲掉。改成合并语义后同类覆盖不会再丢数据。

### 题库自动定位

打开题库滚到当前题（顶部留 78px）。图片懒加载会改变行高，所以用反复对齐直到位置稳定（`requestAnimationFrame` + 120/320/700/1200 ms 复校），牌条加 `aspect-ratio:70/100` 减少抖动。

### 缓存

`index.html` 引 `reader.js?v=N`、`reader.css?v=N`；服务端 html/css/js 走 `no-cache`，图片/图标 7 天长缓存。**改前端必须提版本号**，否则浏览器吃旧脚本。

## 验证过的

- `test_progress.py`（geckodriver + 无头 Firefox，`ALL CHECKS PASSED`）：三个独立浏览器会话（等同三台设备）——A 会话做 1/2/5 题并核对 `progress.json`，B 会话新开即见 3/300 且落在 003，C 会话取消第 2 题后后端变 `[1,3,5]`；另含旧 localStorage 一次性并入、题库 300 项、目录分区 90/90/60/60、`#bank` 直连
- 桌面 1440/1280 与手机 390/320 宽截图目视：顶栏三段、底栏四键不挤（≤650px 用 `repeat(4,minmax(0,1fr))` 四等分，≤380px 字号降到 11px）
- 服务侧：首页/reader/图片 200、404 正常、目录列表 403、局域网不可达、`kill -9` 后 4s 自愈、取不到 tailscale 地址时退出码 3 交给 systemd 重试、`?v=2` 查询串不影响取文件

## 已知限制

- 单用户、无鉴权：进度是明文 JSON，靠 tailnet / 内网边界兜底，不要直接暴露公网
- `--bind tailscale` 依赖 `tailscale` 命令可执行；非 tailnet 环境要显式指定地址
- 题号上限写死 300（前后端一致的 `MAX_Q`），换题库要同步改 `content.js` 与 `serve.py`
